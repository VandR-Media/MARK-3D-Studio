## Реальные изменения

**Независимый сериализуемый бинарный ресурс.** Новый `src/pro-studio/editable-meshdata-binary.js` создаёт `MARKMDB1` (версия 1). Header содержит magic, version, mesh/primitive ID, исходные числа вершин/треугольников, маску UV-наборов, **полный SHA-256 исходного GLB**. Дальше следуют настоящие typed binary `Uint32 indices`, `Float32 positions` и **Float32 UV координаты по каждому углу каждой грани**, раздельно для TEXCOORD_0/1. Source-scoped semantic IDs face/corner/vertex вычисляются детерминированно из SHA/mesh/primitive/face/slot, а не из меняющихся glTF row offsets. Профиль намеренно ограничен исходными indexed TRIANGLES, max 512 faces, max 32768 source rows, двумя Float32 UV-наборами. Скелеты, morph deltas, normals, текстуры, материалы, анимации полностью остаются в исходном GLB и проверяемом экспортном GLB; этот MeshData V1 ещё не является их самостоятельным авторитетным хранилищем.

**Редактируемость.** Новая типизированная `meshdata.translateUv` разрешает пользователю изменить UV0/UV1 **одной исходной грани** либо целого **топологически связанного UV-острова**. Island traversal использует реальные противоположно ориентированные граничные index edges и точно совпадающие UV в двух концах, **без позиционного auto-weld** и без объединения разорванных швов. Изменяются физические Float32 значения MeshData; index/position источника никогда не меняются. Журнал команд `meshDataOperations[]` отдельно сохранён для history/Undo/Redo и строгого детерминированного воспроизведения. До 16 команд, изменённые пары `(face, UV-set)` ограничены 8 текущим glTF экспортёром: больше — fail-closed до commit. Смещения нормированы в диапазоне [-1, 1] на одну операцию; нет unwrap, pack, relax, UV paint, N-gons или свободных topology edits.

**Сохранение `.markscene`.** Исторические файлы из **2 ресурсов** (`manifest.json`, `assets/source.glb`) продолжают открываться без нового MeshData. Новый проект после `meshdata.begin` — строгий ZIP/STORE из **3 ресурсов**, включая `mesh/editable-meshdata.bin`. В manifest отдельно объявлены source SHA, байтовая длина и SHA-256 нового ресурса, `assetManifest` и checksums обновлены. Reader проверяет ZIP CRC, структуру, отсутствие лишних entries, SHA-256 и **побайтовое совпадение бинарного MeshData с повторным исполнением канонических native команд** на исходном GLB. Подмена ресурса, неверная версия, неизвестные поля/операции и конфликт со старыми topology edits отклоняются. Необязательные расширения manifest, которым не угрожают canonical fields, сохраняются при repack.

**glTF export без утраты других потоков.** Рендерер экспортирует из верифицированного бинарного MeshData, сравнивает UV каждого угла и материализует изменённые face-corner rows через проверенный glTF edit kernel Pass25 (`uv.offsetFaceCorners`) — один комплект полных cloned vertex attributes на изменённую пару face/set. Старые POSITION/NORMAL, 70 костей, JOINTS/WEIGHTS, 2 морфа, 3 клипа и PNG/PBR не переписываются. Проверяется соответствие всех поддерживаемых UV углов экспортированного GLB данным MeshData. Отдельно действует строгий запрет topology edits над текущим независимым MeshData без безопасного remap.

**AI Bridge + UI.** В существующий user-granted in-process Bridge добавлены `meshdata.begin`, `meshdata.get`, `meshdata.translateUv` с точными разрешёнными аргументами, проверкой source-scoped face ID, UV set, scope и `delta`. `mesh.getMeshData`, `mesh.getStats`, `mesh.getTopology` при активном MeshData отражают настоящий изменённый GLB / бинарный datablock, а не старый кэш. UV-панель теперь содержит **явную opt-in кнопку создания MeshData**, переключатель `face / island`, реальные UV0/UV1 из актуальных углов, 3D mouse raycast и подтверждение операции. Старые команды P25 остаются при отключённом MeshData. Примитивы и прочий код прежних версий не удалены.

## Ограничения и следующий проход

Текущий файл **персистентен и редактируем**, однако это **первый бинарный MeshData subset для исходных TRIANGLES + UV corners**, а не полный авторитетный Scene & Mesh Core. Он сохраняет исходные индексы/позиции и UV-углы, но ещё не разрешает перемещение позиций, самостоятельную редакцию edges, N-gons/holes, modifiers, скульптинг, изменения костных весов или UV unwrap/pack. Следующий проход №27: расширить независимый MeshData до редактируемых позиций и source-scoped vertex transform с верификацией skin/morph/UV, отдельными бинарными слоями и формальной схемой миграции в постоянное ядро; далее N-gon/holes и модификаторы. Поддержка general vertex move требует сохранения topology ID/skin seams без молчаливых потерь.

**Не доказано:** Android Kotlin APK, Huawei Pura 80 Ultra/EMUI15 на физическом устройстве, полное покрытие Blender, качество Neon Boy. Нет интеграции физического Huawei GPU; HTML/Chromium — только проверяемый прототип. PR draft, merge без разрешения владельца запрещён.
